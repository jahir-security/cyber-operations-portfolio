# SQLMap - SQL Injection - [11-23-2026]

## What This Covers

This lab covers SQL injection vulnerabilities and the use of SQLMap to identify and exploit vulnerable database interactions in web applications. It begins with understanding how websites communicate with databases through SQL queries and how improper input validation and sanitization can allow attackers to manipulate those queries. I studied a basic SQL injection example involving a vulnerable login form and understood how logical operators and SQL comments can alter the intended authentication query. The lab then introduces SQLMap, an automated command-line tool for detecting and exploiting SQL injection vulnerabilities. I practised using SQLMap against GET-based parameters, identifying injectable parameters, enumerating available databases, extracting table names, and dumping records from database tables. I also explored cookie-based testing and the use of intercepted HTTP requests. Finally, I worked through a practical exercise involving a vulnerable login page where I used browser Developer Tools to identify hidden GET parameters, supplied the complete request URL to SQLMap, and performed deeper testing using the `--level=5` option to investigate the application's databases, tables, and stored credentials.

## Key Concepts

* Understanding how web applications interact with databases through SQL queries.
* Understanding the role of Database Management Systems (DBMS) such as MySQL, PostgreSQL, SQLite, and Microsoft SQL Server.
* Understanding SQL injection as a vulnerability caused by improperly validated or sanitized user input.
* Understanding how user-controlled input can modify the logic of an SQL query.
* Understanding the use of logical operators such as AND and OR in SQL injection scenarios.
* Understanding how the expression `1=1` can be used as an always-true condition in a vulnerable SQL query.
* Understanding SQL comment syntax and how injected comments can modify the remaining part of a query.
* Understanding why input validation and proper sanitization are important for protecting database-backed applications.
* Understanding SQLMap as an automated tool for detecting and exploiting SQL injection vulnerabilities.
* Using `sqlmap --help` to explore the available options and flags.
* Understanding the interactive SQLMap wizard using the `--wizard` flag.
* Testing GET-based SQL injection vulnerabilities by passing a complete target URL through the `-u` flag.
* Identifying injectable GET parameters through SQLMap scanning.
* Understanding different SQL injection techniques, including boolean-based blind, error-based, time-based blind, and UNION query injection.
* Enumerating available database names using the `--dbs` flag.
* Enumerating database tables using the `-D` and `--tables` options.
* Extracting records from a specific table using the `-D`, `-T`, and `--dump` options.
* Understanding how SQLMap can identify database technologies and backend server information during testing.
* Understanding cookie-based SQL injection testing using the `--cookie` option to maintain an authenticated session.
* Understanding how intercepted HTTP requests can be supplied to SQLMap using the `-r` option.
* Understanding the difference between GET-based and POST-based SQL injection testing.
* Using browser Developer Tools and the Network tab to inspect HTTP requests and identify parameters that may not be visible in the browser's address bar.
* Performing deeper SQLMap testing using the `--level=5` option when the default scan does not identify the vulnerability.
* Understanding how SQLMap can be used to investigate database contents and retrieve stored application information.

## Commands/Tools Used

```bash
# SQLMap Help:
sqlmap --help

# Interactive Wizard:
sqlmap --wizard


# Testing a GET Parameter for SQL Injection:
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1'


# Enumerating Available Databases:
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' --dbs


# Enumerating Tables in a Database:
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' -D users --tables


# Dumping Records from a Specific Table:
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' -D users -T thomas --dump


# Cookie-Based SQL Injection Testing:
sqlmap -u 'TARGET_URL' --cookie="SESSIONID=abcdef123456"


# Testing an Intercepted HTTP Request:
sqlmap -r intercepted_request.txt


# Practical Lab - Vulnerable Login Page:
# First inspect the login request through the browser Network tab.
# The complete GET request can be obtained from the request details.

# Example request format:
http://MACHINE_IP/ai/includes/user_login?email=test&password=test


# Practical Lab - Database Enumeration:
sqlmap -u 'http://MACHINE_IP/ai/includes/user_login?email=test&password=test' --level=5 --dbs


# Practical Lab - Table Enumeration:
sqlmap -u 'http://MACHINE_IP/ai/includes/user_login?email=test&password=test' -D ai --tables --level=5


# Practical Lab - Extracting Table Records:
sqlmap -u 'http://MACHINE_IP/ai/includes/user_login?email=test&password=test' -D ai -T TABLE_NAME --dump --level=5
```

```sql
-- Example of a Normal Login Query:

SELECT *
FROM users
WHERE username = 'John'
AND password = 'Un@detectable444';


-- Example of SQL Injection Through Improper Input Handling:

-- Injected Password:
abc' OR 1=1;-- -


-- Modified SQL Query:
SELECT *
FROM users
WHERE username = 'John'
AND password = 'abc'
OR 1=1;-- -';
```
